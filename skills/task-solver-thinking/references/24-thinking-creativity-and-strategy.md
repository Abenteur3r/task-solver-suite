# Thinking cards: creativity and strategy

Read the selected card only. Start with a real objective and constraints. Generate alternatives separately from evaluating them, then return a candidate and a test. Novelty alone does not establish usefulness or permission to act.

## 25. Six Thinking Hats

Use when discussion confuses facts, concerns, feelings, benefits, and new ideas. Select a short sequence of perspectives: white for information, red for feelings, yellow for potential value, black for risks, green for alternatives, and blue for managing the process. In a group, everyone uses the same perspective at a time; do not assign permanent personalities to hats.

**Artifact and test:** Distinct observations followed by one decision and evidence gaps. Check that feelings are not presented as facts and hypothetical benefits as measurements. A single agent can vary perspectives, but this does not simulate independent witnesses or establish consensus.

## 26. Red Teaming

Use for a concrete consequential plan, claim, or system. Define the allowed challenge surface, protected boundaries, and the failure that would change the decision. Ask an independent reviewer when available and authorized, or explicitly label a self-review. Seek falsifying cases and plausible adversary responses, not theatrical disagreement.

**Artifact and test:** Findings tied to a specific assumption, evidence, consequence, and mitigation. Test the strongest finding on permitted fixtures or observations and recheck after correction. An absence of findings is limited to the examined scope. This method does not authorize live exploitation, unsolicited contact, or external mutations.

## 27. Abstraction Laddering

Use when the current question appears too narrow or too vague. Ask why the desired action matters to move toward its purpose; ask how that purpose could be met to produce concrete alternatives. Keep the original constraint visible and stop climbing when the frame loses a useful connection to the task.

**Artifact and test:** The original frame, a better bounded question, and two feasible approaches. “How do we add a dashboard?” might become “How can an operator recognize the next exception?” Test the new frame with the intended user or supplied evidence. Reframing must preserve the user's goal rather than silently replacing it.

## 28. Conflict Resolution Diagram

Use when opposing demands may serve compatible needs. Write the shared objective, each side's underlying need, and the demanded action serving it. Inspect the assumption behind every claimed necessity and the assumption that both actions cannot coexist. Propose a changed condition that meets both needs.

**Artifact and test:** Objective → two needs → conflicting demands, with the challenged assumption and a bounded trial. Example: immediate access and careful review may coexist through limited provisional access followed by broader authorization. Check both needs with the relevant stakeholders. A fixed resource shortage or binding restriction may require allocation, not an invented resolution.

## 29. Zwicky Box

Use when a solution can be assembled from substantially independent dimensions. Choose a few meaningful dimensions and list distinct feasible options under each. Combine options, eliminate incompatible combinations, and select contrasting candidates for evaluation. Keep the search small enough to inspect.

**Artifact and test:** A dimension/options table, compatibility notes, and a candidate configuration. For an information service, dimensions might be input channel, retrieval method, and delivery format. Check whether a supposedly independent choice changes another dimension's feasibility or cost. The number of combinations is not the number of viable innovations.

## 30. Productive Thinking Model

Use when a novel, bounded problem needs a full path from understanding to action. Establish the current situation; define observable success and constraints; formulate the question that would unlock progress; generate varied answers; refine a coherent candidate against the criteria; assign the resources and actions needed to test it. Revisit the frame if later work exposes a mistaken premise.

**Artifact and test:** A compact problem-to-action record with alternatives considered and a first experiment. Verify that the chosen idea meets all essential criteria and has an owner and feasible resources. Use a narrower card when a complete creative process would add ceremony without changing the decision.

## 31. Inversion

Use when imagining failure exposes overlooked prevention. Specify the desired outcome, then describe a few concrete ways it could be defeated. Separate likely mechanisms from vivid speculation. Translate the consequential, controllable mechanisms into preventive actions and early warning signals.

**Artifact and test:** Failure mechanism → evidence → prevention → trigger, with an owner. Example: a review fails because the reviewer cannot access the artifact; test access using the intended permission level. A premortem is one application. Avoid treating every imaginable disaster as a requirement or confusing an imagined failure with an observed one.

For a measured requirement conflict that survives reframing, use the lightweight [TRIZ trade-off procedure](../../task-solver-triz/SKILL.md). Source context is recorded in the [source ledger](sources.md).
