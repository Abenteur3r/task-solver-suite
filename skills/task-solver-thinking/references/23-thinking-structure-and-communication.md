# Thinking cards: structure and communication

Read the selected card only. Choose the artifact that lets the intended audience make the next decision. Clear presentation preserves uncertainty; it does not repair weak evidence by making it sound confident.

## 17. Fermi Estimation

Use when a missing order of magnitude blocks action and direct measurement is unavailable or disproportionately costly. Decompose the quantity into interpretable factors with units. Assign plausible ranges and sources or explicit assumptions. Calculate a central scenario and bounds; preserve dependencies between factors rather than multiplying incompatible extremes.

**Artifact and test:** An equation, low/base/high scenarios, and the dominant uncertainty. Example: daily storage equals users × items per user × bytes per item, plus explicitly modeled replication. Check dimensional consistency and compare with one independent estimate. Measure the factor most likely to change the decision. A rough range is not a forecast distribution.

## 18. Ladder of Inference

Use when a disputed conclusion may depend on selective observation or assumptions. Separate the observed event, selected details, interpretation, assumptions, conclusion, and proposed action. Generate a plausible alternative interpretation and identify the evidence that distinguishes them.

**Artifact and test:** A short claim/evidence/assumption table and a clarifying observation. Example: an unanswered message establishes no reply, not unwillingness to collaborate. Check the relevant context before acting on motive. Use direct logical analysis for a formal proof; this tool inspects how a judgment was formed rather than proving every inference valid.

## 19. Issue Trees

Use to split a large question into answerable parts. Choose one decomposition rule per level: cause, population, time, process stage, or candidate action. Make branches cover the defined scope with minimal overlap, then attach evidence or a next test to the important leaves.

**Artifact and test:** A question tree whose answered leaves would resolve the parent question. For a cost increase, a price/volume decomposition is different from a team-by-team breakdown; avoid mixing them at one level. Check a residual “unexplained” category to expose gaps. Use a causal map when feedback between branches dominates.

## 20. Concept Map

Use when terminology or conceptual relationships prevent shared understanding. Choose a focus question, define the important terms, and connect them with labeled propositions such as “contains,” “requires,” or “is an example of.” Include a concrete example and boundary case for easily confused concepts.

**Artifact and test:** A small semantic map and any unresolved definitions. Read each edge as a sentence and verify it against the domain. For example, a prediction is not the same thing as a decision made from it. Avoid treating adjacency as causation or adding every known term; retain only relations relevant to the focus question.

## 21. Minto Pyramid

Use when analysis is sufficient but a reader needs the recommendation quickly. State the answer to the reader's actual question. Group the supporting reasons into distinct propositions, then attach the evidence that supports each. Order the groups by the decision's logic rather than the chronology of the investigation.

**Artifact and test:** A concise recommendation with supporting reasons and visible caveats. Check whether each lower-level statement supports its parent and whether the top statement says more than the evidence permits. If a missing fact determines the answer, lead with the conditional decision or unresolved question rather than inventing certainty.

## 22. Situation-Behavior-Impact

Use to draft feedback about an observed interaction. Specify the situation, describe observable behavior without a personality label, and explain the impact from the speaker's perspective. Invite relevant context and make a concrete request when appropriate.

**Artifact and test:** A short feedback draft that the recipient could recognize. Example: “In yesterday's handoff, the configuration version was missing, so I could not reproduce the result. Please attach it next time.” Check that dates, behavior, and claimed impact are supportable; separate intent from effect. Drafting feedback does not authorize sending it.

## 23. Backcasting

Use when the desired future state is clear but the route is not. Define observable success and its date. Work backward through necessary preconditions, resource commitments, and irreversible lead times. Then run the sequence forward to check that it is feasible from the current state.

**Artifact and test:** A prerequisite chain with the nearest actionable milestone and latest safe dates. For an event demo, access, integration, rehearsal, and transfer must precede the presentation. Challenge any dependency described only as “then we scale.” If the endpoint is disputed, resolve that choice before constructing an elaborate plan.

## 24. After Action Review

Use after a bounded episode, whether it succeeded or failed. Record the intended outcome, observed outcome, material differences, and the evidence for their causes. Distinguish useful decisions made under uncertainty from fortunate outcomes. Include what should continue as well as what should change.

**Artifact and test:** A short account and one or two owned changes with review dates. Example: a timely release may have succeeded only because an external dependency recovered; preserve the fallback work rather than crediting the schedule. Check the proposed lesson against another episode or a future trial before making it a permanent rule.
