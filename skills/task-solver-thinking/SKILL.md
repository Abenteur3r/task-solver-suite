# Select a thinking method

Apply only the sections needed for the requested result. Preserve the distinction between a plan, review, implementation, and execution, and respect the user's limits on testing or external actions.

Use an explicitly selected or available format/platform specialist for its exact workflow. Sibling-skill links are conditional handoffs: read them only for a concrete dependency and when that skill is available. A single-domain task does not require the suite coordinator.

Use for difficult framing, diagnosis, choice, or communication. Follow reliable procedures directly for obvious tasks. These **31 methods in four families** are a menu.

Choose by the needed artifact and blocking uncertainty. Read one family and its selected card; honor explicit method requests. Add another only for a distinct remaining question. Stop when evidence supports action or the analysis budget ends.

## Diagnosis and systems — [cards 01–08](references/21-thinking-diagnosis-and-systems.md)

| ID / method | Trigger | When not to use |
| --- | --- | --- |
| 01 First Principles | Conventions constrain design | A verified procedure suffices |
| 02 Five Whys | One incident needs causal tracing | Several causes need enumeration |
| 03 Ishikawa Diagram | Cause candidates span several categories | Cause is already reproduced |
| 04 Iceberg Model | Recurring events resist local fixes | Only one event is known |
| 05 Connection Circles | Variables influence each other | Relationships are merely semantic |
| 06 Balancing Feedback Loop | Correction overshoots or resists change | No target or feedback exists |
| 07 Reinforcing Feedback Loop | Growth or decline compounds | Growth is externally imposed |
| 08 Cynefin Framework | Analysis versus probing is unclear | The response is already established |

## Decisions and uncertainty — [cards 09–16](references/22-thinking-decisions-and-uncertainty.md)

| ID / method | Trigger | When not to use |
| --- | --- | --- |
| 09 Decision Matrix | Options share several criteria | A hard constraint decides |
| 10 Eisenhower Matrix | Urgency crowds out importance | Dependencies determine sequence |
| 11 Impact-Effort Matrix | A backlog exceeds capacity | Impact estimates lack any basis |
| 12 Hard Choice Model | Decision effort needs calibration | Immediate containment is required |
| 13 Confidence Determines Speed vs. Quality | Evidence determines build depth | Mandatory quality determines effort |
| 14 Pareto Analysis | Measured contributors differ greatly | Categories overlap or data are absent |
| 15 OODA Loop | Conditions change during execution | Feedback arrives too late to help |
| 16 Second-Order Thinking | A gain may shift costs downstream | Immediate effects settle the decision |

## Structure and communication — [cards 17–24](references/23-thinking-structure-and-communication.md)

| ID / method | Trigger | When not to use |
| --- | --- | --- |
| 17 Fermi Estimation | A missing magnitude blocks action | Accurate data are readily available |
| 18 Ladder of Inference | Conclusions outrun observations | The task is formal proof checking |
| 19 Issue Trees | A large question needs decomposition | Coupled feedback dominates |
| 20 Concept Map | Terms and relationships are confused | A causal mechanism is required |
| 21 Minto Pyramid | An audience needs a clear recommendation | Evidence cannot support one yet |
| 22 Situation-Behavior-Impact | Feedback needs observable specificity | Facts are disputed or unverified |
| 23 Backcasting | A defined future needs prerequisites | The endpoint remains undecided |
| 24 After Action Review | An episode can improve future practice | No outcome has occurred yet |

## Creativity and strategy — [cards 25–31](references/24-thinking-creativity-and-strategy.md)

| ID / method | Trigger | When not to use |
| --- | --- | --- |
| 25 Six Thinking Hats | Discussion mixes incompatible thinking modes | One factual lookup resolves it |
| 26 Red Teaming | A consequential plan needs challenge | No concrete plan exists |
| 27 Abstraction Laddering | The problem frame is too narrow | Scope is contractually fixed |
| 28 Conflict Resolution Diagram | Opposing demands hide shared needs | Genuine fixed scarcity decides |
| 29 Zwicky Box | Solutions combine independent dimensions | Dimensions cannot vary independently |
| 30 Productive Thinking Model | A novel problem needs ideation through action | A narrower method suffices |
| 31 Inversion | Failure conditions reveal prevention | Failure mechanisms are already controlled |

Each card specifies an artifact and test. Report results, evidence, uncertainty, and action. Check assumptions behind diagrams and scores.


For a consequential decision, the optional [decision record](assets/templates/decision_record_template.md) can preserve alternatives, evidence, and revision triggers.
